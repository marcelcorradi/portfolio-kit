# Quality Checklist

Run this before presenting any page or case study as "done". Derived from the common mistakes that get portfolios rejected and from what design and hiring leaders actually look for. The goal is to catch the predictable failure reasons — systematically, every time.

For each item, either confirm it passes or flag it. If it fails, fix it or route it back to the right specialist skill before calling the work done. It's fine to present with a known gap *as long as you name the gap explicitly* (e.g. "cover image is a placeholder", "results metric still needed from the owner").

## Content quality

- [ ] **Curation / role alignment** — Does this project belong in this portfolio, given the owner's target role? Is it one of their best, or does it dilute? (Quality over quantity — a weak case drags down the perceived level of all the others.)
- [ ] **Leads with results (inverted pyramid)** — Does the case/home open with the outcome and hook, not a slow chronological build-up?
- [ ] **Quantified results** — Are concrete metrics present where they exist (counts, adoption, %, before/after, people affected)? Recruiters look for evidence of real impact. (Not every case is numeric — an authorial project may lead with the thing itself. Don't invent numbers to fill this.)
- [ ] **Self-reflection** — Does the case show learnings / what they'd do differently, not just a task list ("I did X, then Y")? This demonstrates critical thinking.
- [ ] **Differentiator visible** — Does the owner's core differentiator (recorded in project-decisions.md) come through where relevant? This is the single thing the whole site exists to prove.
- [ ] **No inventing** — Every claim traces to a real fact the owner gave. No fabricated metrics, projects, or outcomes.

## Craft / carefulness

- [ ] **No typos or grammar errors** — The portfolio itself is a work sample; carelessness reads as poor attention to detail.
- [ ] **Visual consistency** — Consistent typography, spacing, and UI treatment across the page and between sections.
- [ ] **Personalization** — Doesn't look like an unmodified popular template. Has intentional, specific choices (the "signature").

## Web standards (this is a website, so these are non-negotiable)

- [ ] **Responsive** — Works down to mobile; body never scrolls horizontally.
- [ ] **Accessible** — Sufficient color contrast, visible keyboard focus, semantic structure, reduced-motion respected. A portfolio that fails accessibility undercuts its own craft claim.
- [ ] **Navigation clarity** — A visitor can find the work and contact without hunting. No dead ends.

## Home-specific

- [ ] **Hook in the first screen** — Name, what they do, and why they're worth reading, above the fold.
- [ ] **Featured work is scannable** — Cards with meaningful titles, short descriptions, skill + attribute tags (e.g. fintech, e-commerce), whole card clickable with hover feedback.
- [ ] **Contact present** — Email and the owner's key links (LinkedIn, GitHub, portfolio-relevant profiles) reachable.

## Case-specific

- [ ] **Reads like an article** — Single column, clean, focused on readability (Medium-like), not a cluttered dashboard.
- [ ] **Visual context** — Shows the work in context, before/after where it helps, clean final UI.
- [ ] **Clear scope up front** — Project type, the owner's role, timeframe, tools.
